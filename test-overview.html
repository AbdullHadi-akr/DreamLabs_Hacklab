01The strategies

Each request to Dream-1 returns 48 joint targets (2.4 s). The strategy decides how much of that is executed and how consecutive plans are joined.

chunk

Execute all 48 steps, then ask again. Runs 2.4 s without correction. The previous default.

crossfade-N new default: N = 30

Ask again every N steps and blend smoothly from the old plan to the new one.

receding-N

Execute only the first N steps, discard the rest, ask again.

ensemble-N

Average all plans that cover a moment, weighted (as in ACT).

06Cameras and Model X-Ray

Do the camera images reach the model correctly, and what does Dream-1 look at?

Camera pipeline

  • 8 / 8 deliberately injected faults detected: swapped, duplicate, upside down, colours, frozen, 600 ms delay, black, zoom
  • Clean runs without false alarms: delay 0 ms, 5 frames/s
  • Camera tilted, light dimmed, image noise, camera moved: images arrive correctly
  • Dream-1 uses the cameras: blanking one moves the plan by up to 9.5 cm (top) or 5.9 cm (wrists)

Model X-Ray

  • Dream-1 is deterministic: same request, same plan (0.0 cm).
  • Shortly before and during the grasp it follows the image, not the word: with "banana", "orange" or "bottle" in the prompt it stays with the apple (0 of 3).

07Findings and measurement errors fixed

Same scene does not mean same result

The GPU renders minimally differently (≈ 0.01 % of the pixels by one grey level). Dream-1 reacts to that, so runs of the same scene diverge. A single trial says little, so every comparison used many pairs.

Fixed during the night

  • Artificial delay: the client replaced ~11 steps of every new plan with the old one.
  • A trial that hung in standby counted as a failure; such trials are now excluded.
  • "Dream-1 is full": the tool now waits instead of ending the run.
  • Camera check: false "frozen" alarm in dim light.
  • X-Ray: heatmap only on the most important camera; the language probe now answers at every moment.

08Open points

  • The orange never works (0 / 50), the banana only with crossfade-30 (3 / 8). The fruit slips out of the closed gripper, probably due to friction or grasp position.
  • "Placed next to the bowl" is the most common remaining failure with crossfade-30.
  • receding-24 vs. crossfade-30 directly: barely measured (5/12 vs. 6/12). Both are clearly better than chunk.
  • Whether Dream-1 uses the object word early in the approach is still open.
  • The Dream input check has to be run by a person: python -m dream.input_check 4932209e541e
